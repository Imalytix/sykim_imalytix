## 오늘 내린 핵심 결정 — 왜 이렇게 했는지

- **DINO는 `main`에서 기본 꺼짐, `research/dino`에서만 다시 켜짐** (`.env.local`의
  `IMALYTIX_ENABLE_DINO`). 꺼둔 이유: `app/icon.png`(로고, 사진도 AI생성물도
  아님)를 넣었더니 AI 확률 83%로 오판정 — 코드 버그가 아니라 학습 데이터가
  좁아서(real=Unsplash 큐레이션 사진만, AI=Stable Diffusion만) 생기는 일반화
  문제로 확인됨. `research/dino` 브랜치의 목적 자체가 이 문제를 데이터
  다양화(FLUX/Midjourney 등)로 풀어보면서 품질이 얼마나 개선되는지 계속
  실험하는 것 — 여기서 켜져 있는 건 의도된 상태.
- **Supabase Storage/로그 마이그레이션 완료** — 업로드 이미지·요청 로그·pHash 전부
  Supabase에 실제로 쌓이는 것까지 확인함(`images` 테이블 12행, `request_logs`
  테이블 생성 확인). Vercel 배포 시 로컬 디스크 휘발 문제는 해결된 상태.
- **`next.config.ts`에 `serverExternalPackages: ["sharp", "ws"]` 추가** — Supabase
  의존성이 끌고 온 `ws` 라이브러리가 "Couldn't load fs/zlib" 콘솔 경고를 냈던 것
  수정. 서버 재시작해야 반영됨.

## 진행 중이던 작업 — 중단된 상태

**`lib/` 폴더 코드 리뷰(`/code-review lib`)가 8개 관점 중 1개(line-by-line)만
끝나고 중단됨.** 지금까지 나온 발견 5건(요약):
1. DINO의 evidence가 "real 판정"일 때도 항상 severity를 채워서, aggregator가
   방향 구분 없이 무조건 점수를 더하는 게 아닌지 (`lib/analysis/dino.ts`)
2. evidence 설명 문구가 real 판정일 때도 "AI 생성으로 판정했다"고 고정 출력
3. Supabase Storage 업로드 실패 시 로컬 폴백이 Vercel에서는 사실상 "조용한
   데이터 유실"이 될 수 있음
4. `image_path`가 `supabase://...`/로컬 경로 두 형식이 섞여 저장돼 나중에
   소비하는 코드가 구분 못 할 수 있음
5. `ensureBucket`의 `getBucket()` 에러를 무시해서, 권한 문제 시 매 요청마다
   같은 실패를 반복할 수 있음

전부 아직 **검증(verify) 전 후보**일 뿐 확정된 버그는 아님 — 나머지 7개 관점
(removed-behavior, cross-file, reuse, simplification, efficiency, altitude,
conventions) + 검증 단계가 안 끝났습니다. 이어가려면 이 파일과 함께
"`/code-review lib` 이어서 계속해줘"라고 하면 됩니다.
