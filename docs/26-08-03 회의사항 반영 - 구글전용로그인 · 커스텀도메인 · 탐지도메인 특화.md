## 1) 로그인을 Google 전용으로 단순화

- `app/login/page.tsx`에서 이메일/비밀번호 회원가입·로그인 폼, 로그인↔회원가입 토글 전부 제거 — 이제 **Google 버튼 하나**와 "로그인 없이 계속 사용하기" 링크만 남습니다.
- 카카오 버튼은 지난 라운드처럼 코드는 남기고 주석 처리 상태 유지(대시보드 미설정) — 이번 결정이 "구글만"이라 굳이 다시 켤 필요는 없어 보이지만, 나중에 마음 바뀌시면 주석만 풀면 바로 켜집니다.
- 백엔드(스키마/트리거/RLS)는 로그인 방식과 무관하게 이미 Supabase Auth 표준 흐름을 그대로 쓰고 있어서 손댈 게 없었습니다 — `handle_new_user` 트리거는 이메일 가입이든 OAuth든 동일하게 `auth.users` insert 시점에 발동합니다.

### 유저별 통계 — 없어서 추가함

기존엔 `v_user_activity_log`(요청 1건=1행)만 있어서 "이 사람이 총 몇 번 썼는지" 보려면 매번 직접 집계 쿼리를 짜야 했습니다. **`v_user_stats` 뷰를 새로 추가**했습니다:

```sql
select * from v_user_stats order by total_requests desc limit 20;
```

컬럼: `user_id`, `email`, `signed_up_at`(가입일), `total_requests`(총 분석 횟수), `ai_generated_count`/`real_count`(판정 분포), `avg_score`(평균 점수), `last_request_at`(최근 활동일). "누가 제일 많이 쓰는지", "가입만 하고 안 쓰는 사람이 얼마나 되는지" 같은 질문에 바로 답 나옵니다.

## 2) Vercel 커스텀 도메인 교체 방법 (`www.imalytix.com` 예시)

### 도메인 구매
가비아·후이즈(국내) 또는 Namecheap·Cloudflare Registrar(해외) 아무 데서나 구매하시면 됩니다 — 특별히 Vercel과 연동이 더 쉬운 업체는 없고, 어디서 사든 절차는 동일합니다(DNS 레코드만 맞추면 됨).

### Vercel에 도메인 연결
1. Vercel 프로젝트 → **Settings → Domains** → 도메인 입력(`www.imalytix.com` 또는 `imalytix.com`) → Add
2. Vercel이 필요한 DNS 레코드를 알려줍니다 — 보통:
   - **apex 도메인**(`imalytix.com`)이면 **A 레코드**를 Vercel이 알려주는 IP로
   - **서브도메인**(`www.imalytix.com`)이면 **CNAME 레코드**를 `cname.vercel-dns.com`으로
3. 도메인 구입처의 DNS 관리 화면(가비아면 "DNS 관리" 메뉴 등)에 가서 그 레코드를 등록
4. 보통 몇 분~몇 시간 내 반영(전파). Vercel Domains 화면에서 초록색 체크 뜨면 완료

### apex(`imalytix.com`) vs www(`www.imalytix.com`) — 둘 다 등록 권장
하나만 사서 다른 하나로 자동 리다이렉트 걸어두는 걸 추천드립니다 — Vercel Domains에서 "Redirect to" 옵션으로 간단히 설정 가능합니다 (예: `imalytix.com` 접속 시 `www.imalytix.com`으로 자동 이동).

### 도메인 교체 후 반드시 해줘야 하는 것 — Supabase Redirect URL 추가
새 도메인도 로그인이 되려면, Supabase 대시보드 → Authentication → URL Configuration → **Redirect URLs**에 추가해야 합니다:
```
https://www.imalytix.com/auth/callback
```
(기존 `localhost`/Vercel 기본 도메인 항목은 그대로 둬도 무방 — 로컬 개발은 계속 필요합니다)

Google Cloud Console 쪽 OAuth 설정은 **변경 불필요**합니다 — 거기 등록된 리다이렉트 URI는 Supabase의 콜백 주소(`https://<project-ref>.supabase.co/auth/v1/callback`)라서 우리 앱 도메인이 바뀌어도 그대로입니다.

## 3) 탐지 도메인 특화 — 얼굴 편집 / 중고거래 사기

`lib/vision/prompts.ts`의 콘텐츠 유형별 체크리스트(`[face]`, `[object]`)를 두 도메인에 맞춰 보강했습니다. LLM 프롬프트만 바꾼 것이라 **재배포만 하면 바로 반영**되고, DB/스키마 변경 없습니다.

### 3-1) 얼굴 편집 탐지 (프로필 사기·로맨스 스캠)

기존 체크리스트(좌우 대칭·피부질감·치아입술·귀헤어라인)에 face-swap/딥페이크 프로필 사진에서 실제로 자주 나타나는 항목을 추가했습니다:
- **얼굴 합성 경계** — 턱선·헤어라인·목 연결부의 블렌딩 흔적(경계 흐림, 색상·톤 단절)
- **얼굴 vs 몸통/배경 조명 불일치** — 얼굴만 별도로 보정·합성된 프로필 사진에서 흔함
- **안경·귀걸이·목걸이 왜곡** — 얼굴 합성 시 소품이 함께 왜곡되는 경우가 많아 좋은 단서
- **피부 질감 격차** — 얼굴만 과매끈, 목·손은 그대로인 경우
- **시선/초점 불일치** — 고개 각도와 눈동자 방향이 부자연스럽게 어긋나는지

### 3-2) 중고거래 사기 (번개장터·중고나라)

`[object]` 체크리스트에 상품 사진 맥락에 맞는 항목을 추가했습니다:
- **촬영 맥락 불일치** — "개인이 집에서 촬영"이라는 게시글 맥락에, 스튜디오 수준 조명·완전 무배경 처리는 어울리지 않음(카탈로그 사진처럼 보이면 의심 신호)
- **사용감 자연스러움** — 스크래치·먼지·생활공간 배경이 자연스러운지, 지나치게 매끈한지
- **다중 반사광 모순** — 이미지 내 여러 면의 반사광 방향/색상이 서로 안 맞으면 AI 렌더링 특유의 신호
- **경계 이질감** — 제품이 배경에서 "오려붙인" 것처럼 보이는지(edge halo, 배경/피사체 해상도·노이즈 격차)

### 솔직히 말씀드릴 한계

이 프로젝트가 하는 건 어디까지나 **"이 픽셀이 AI로 생성/편집됐는가"** 판별이지, **"이 사진이 다른 게시글에서 도용된 진짜 사진인가"**를 잡는 건 아닙니다. 중고거래 사기의 상당수는 AI 생성 이미지가 아니라 **타인의 실제 상품 사진을 도용**하는 패턴이라, 그건 이 파이프라인(단일 이미지 포렌식)으로는 원천적으로 못 잡습니다 — 그걸 잡으려면 역이미지 검색이나 "이미 우리 DB에 올라온 다른 게시글 사진과 동일한지" 비교하는 별도 기능(예: phash로 여러 매물 간 사진 중복 탐지)이 필요한데, 이건 이번 프롬프트 튜닝과는 다른 범주의 기능이라 별도로 논의가 필요합니다. 필요하시면 다음에 설계해드릴 수 있어요.
