## 1. 버그 수정 — PNG 파일의 EXIF 오탐

**증상**: AI로 생성된 이미지(대부분 PNG 형식)를 분석해도 "촬영 정보가 확인되었습니다"라고 잘못 표시됨. 실제로는 카메라로 찍힌 기록이 전혀 없는데도 그렇게 나옴.

**원인**: EXIF를 읽는 라이브러리(`exifr`)가 PNG 파일에서는 진짜 촬영 정보(제조사, 모델명, GPS 등)가 하나도 없어도 이미지의 기본 구조 정보(가로/세로 크기, 색상 방식 등)를 항상 돌려줌. 코드가 "뭔가 돌려받았다 = EXIF 있다"로 잘못 판단하고 있었음. (JPEG는 이 문제가 없음 — EXIF가 없으면 아예 빈 값을 돌려줌)

**수정**: 카메라 제조사·모델명·촬영일시·GPS 등 **진짜 촬영 정보에 해당하는 항목이 하나라도 있을 때만** "확인됨"으로 판단하도록 변경.

**검증 결과**:
| 테스트 파일 | 수정 전 | 수정 후 |
|---|---|---|
| AI 생성 파라미터만 있는 PNG | 확인됨 (오탐) | **확인 안 됨** ✅ |
| 실제 카메라로 찍은 JPEG | 확인됨 | 확인됨 (정상 유지) |

## 2. 문구 수정

### "AI 이미지 탐지" 문구 제거
Chrome 웹스토어 심사 피드백 반영 — 3곳에서 제거하고 브랜드명만 남김:
- 웹사이트 브라우저 탭 제목
- 크롬 익스텐션 이름
- 개인정보처리방침 페이지 내 서비스명 언급

### "웹에서 동일한 이미지가 발견되지 않았습니다" → "자사 DB에서..."
실제로는 웹 전체가 아니라 우리 자체 DB(과거 분석 이력)만 검색하는 기능이라, 표현이 과장돼 있었음. 웹앱과 크롬 익스텐션 양쪽 다 수정.

## 3. 홈페이지 개편 — 실제 디자인 반영

이 부분은 시행착오가 좀 있었어요. 순서대로 정리합니다.

### 3-1. 히어로(첫 화면) 장식
- **1차 시도**: 참고 프로토타입 사이트(Netlify)의 실제 소스코드를 그대로 분석해서, 이모지 16개가 원형으로 배치되는 "링" 형태로 구현
  - → 배치 계산에 버그가 있어 카드끼리 겹쳐서 지저분하게 보임 → 수정
  - → 그런데 이후 디자이너 원본 목업(Figma)을 다시 확인해보니, 실제 의도는 이모지 링이 아니라 **실제 사진 몇 장이 느슨하게 흩어진 형태**였음
- **최종**: Figma 목업에서 실제 사진(카메라, 음식, 소파, 인물 등)이 배치된 부분을 그대로 잘라내어 좌/우에 배치. 업로드 박스·버튼과 겹치지 않도록 가운데는 비워서 잘랐음

### 3-2. "이런 상황에서 쓰세요" 카드 (이용 사례)
- 기존: 그라데이션 배경 + 이모지 + 직접 입력한 문구 조합(6장)
- 변경: Figma 목업에서 **완성된 카드 이미지 5장**(데이팅앱/중고거래/음식리뷰/숙소·부동산/SNS)을 통째로 잘라내어 그대로 사용 — 배지·문구·일러스트가 이미 이미지 안에 그려져 있어 텍스트를 따로 겹칠 필요가 없어짐
- 원래 있던 "뉴스·미디어" 카드는 목업 기준 5장 구성에 맞춰 제외
- **좌측으로 천천히 계속 흘러가는 자동 스크롤(마퀴) 애니메이션** 추가 — 마우스를 올리면 멈춤

### 3-3. 크롬 익스텐션 홍보 섹션
- 기존: 정적 플레이스홀더 카드("Imalytix" 아이콘 + 텍스트)
- 변경: 실제 데모 영상 삽입. **화면에 보일 때만 재생하고, 스크롤로 벗어나면 자동 정지**(항상 재생하는 것보다 리소스 부담이 적음)
- 문구도 참고 프로토타입과 동일하게 맞춤: "브라우저 익스텐션으로, 보던 화면 그대로"

### 3-4. 자잘한 수정
- "이미지 검증하기" 버튼 색을 한 차례 잘못 바꿨다가(스크린샷만 보고 판단) 디자인 원본 파일을 픽셀 단위로 확인해서 원래 색(`#52bdff`)으로 되돌림
- 분석 중 로딩 화면: 체크보드+진행바 버전을 시도했다가, 디자인 원본과 라이브 프로토타입 둘 다 확인한 결과 원래의 "아이콘 + 5문장 순환 + 경과시간" 구성이 맞는 것으로 확인되어 그대로 유지
- 업로드 박스 문구 "Upload"(영어) — 디자인 파일엔 한글로 되어 있었지만, 실제 라이브 프로토타입 소스코드를 확인해보니 영어 "Upload"가 맞아서 그대로 유지
